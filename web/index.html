A bKash client that runs natively on your PC

bKash ships as a Flutter app, so there is no Kotlin to port — the logic is ARM64 machine code inside a 30 MB Dart snapshot. This project recovers what is recoverable and rebuilds it as a native Rust desktop binary. No emulator. No Android.

Download / build View source 
git clone https://github.com/NurMohammadDuari/bkash-desktop
cd bkash-desktop
cargo build --release
./target/release/bkash_desktop

What makes this different

Every other route to running an Android banking app on a desktop goes through an emulator, a VM, or a cloud device farm. This one doesn't.

No emulator layer

A native ELF binary. There is no Android runtime in the process at all — not even as a library.

Decodes the real artifact

A dependency-free Rust ELF reader locates and parses the Dart AOT snapshot sections and header. Ghidra found 0 procedures in the same file.

Evidence, not guesses

Gateways, endpoints and crypto markers were recovered from the shipped binary. Every inference is labelled as one.

Testable offline

48 unit tests run with no network. The backend is a trait; the simulated backend exercises every screen.

Install

Requires Rust 1.75 or newer and a GPU with OpenGL 3.3 or Vulkan.

cargo install --path .

# or run without installing
cargo run --release --bin bkash_desktop

Two more binaries ship alongside it: bkanalyze decodes the Dart snapshot, and bknative exposes the recovered API surface from the command line.

Questions people actually ask

Can I send real money with this?

No. It ships with an offline simulated backend and performs no live financial transactions. The live backend refuses to create a session. This is a research and interoperability project.

Why can't it log in to the real bKash service?

The blocker is not crypto — that part is implemented. It is that no request or response body was ever captured. The endpoints auth/pre-init and otp/verify are known only as strings plus fragments like PreInit{aesKey:, so the field names and token format are inferred. Building a login on inferred schemas would fail at the server, or worse, appear to work while being wrong.

Is this legal?

It contains no bKash code or assets. It is an independent reimplementation built by static analysis of a publicly obtainable APK, for research and interoperability. It is not affiliated with or endorsed by bKash.

Will it bypass emulator detection on the real app?

No, and it will not. The real app ships libtoolChecker.so and libsecurity_lite.so for tamper and emulator detection. Defeating those controls is out of scope for this project.

Why is the Java decompilation in the repo so thin?

Because there is almost nothing there. Decompiling 26,234 files yields an application whose entire entry point is a three-line onCreate calling super. All the real code is Dart AOT.

Can I help finish the port?

Yes — see docs/PORT-NOTES.md. The highest-value contribution is a capture from a real device on your own account, which converts the inferred API schema into observed truth.
